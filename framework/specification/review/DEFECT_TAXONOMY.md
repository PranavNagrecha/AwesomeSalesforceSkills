# Defect taxonomy

Use one primary category and optional contributing categories.

- `SCOPE` — wrong milestone, unapproved expansion, placeholder completeness.
- `INTEGRITY` — omitted code/log, unreconstructable bundle, false report, checksum issue.
- `INPUT` — typed validation or conditional requirement failure.
- `TARGET` — wrong/ambiguous org, project, job, test, snapshot, or comparison identity.
- `HOST` — plugin/discovery/subagent/MCP/hook/cloud behavior mismatch.
- `STATE` — invalid run transition, checkpoint, resume, or terminal status.
- `CONTEXT` — irrelevant/broad selection, overflow, transcript, compaction, contamination.
- `KNOWLEDGE` — missing/stale/incorrect Salesforce guidance or source governance.
- `TOOL` — upstream call, normalization, error class, pagination, timeout, version drift.
- `EVIDENCE` — provenance, stable ID, target mismatch, truncation, classification, contradiction.
- `CLAIM` — unsupported, overbroad, wrong confidence, missing unknown, unsafe recommendation.
- `REVIEW` — deterministic lint/reviewer/policy failure or lack of independence.
- `SECURITY` — authority, bypass, injection, secret, path, dependency, retention.
- `QA` — weak ground truth, missing lane, bad grader, benchmark leakage, unrun claim.
- `UX` — install, doctor, command, result, error, documentation.
- `COMPAT` — regression, legacy export, existing agent/command/MCP break.
- `MARKET` — product does not beat baseline or solve a repeated user job.

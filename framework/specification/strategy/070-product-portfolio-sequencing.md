# Product portfolio sequencing

## Release cohort A — blockers and trust

### P01 Deployment Failure Triage

Proves native installation, target identity, job normalization, optional project inspection, context selection, evidence graph, independent review, and read-only policy.

### P02 Apex Test Failure Triage

Proves reuse, shared-root-cause clustering, source/automation context, long results, second-task isolation, and compaction-aware behavior.

### P03 Access Path Explainer

Proves admin/security value, layered org evidence, data minimization, and first-blocking-control explanations.

These three require the strongest host and scratch-org qualification before stable claims.

## Release cohort B — engineering decision intelligence

### P04 Change Impact Planner

Combines source, dependencies, permissions, automation, tests, package boundaries, and rollout/rollback planning.

### P05 Automation Transaction Profiler

Explains order, re-entry, async boundaries, DML amplification, and likely limit/behavior hotspots.

### P06 Release Readiness Review

Aggregates product evidence into pre-release risk, test, security, dependency, drift, sequencing, and rollback review.

These become flagship only when actual usage demonstrates that shared primitives improve quality rather than creating a generic workflow engine.

## Release cohort C — beta portfolio

- P07 Security Posture Review
- P08 Integration Incident Triage
- P09 Data Migration Reconciliation
- P10 Org Health Assessment
- P11 Agentforce Quality Engineer
- P12 Multi-Org Drift Analysis

Each must have an end-to-end fixture path, typed evidence, independent review, host discovery, limitations, and at least one failure/partial case. They remain beta until behavioral qualification exists.

## Next-product gate

Do not add more products because a role or cloud is uncovered. A candidate must show:

- frequent/high-cost user job;
- evidence that can be obtained safely;
- measurable required findings;
- a distinct product outcome rather than an agent persona;
- reuse of the framework without bloating context;
- design-partner demand or repeated incident evidence.

Current likely next candidate after V2 proof: permission/access remediation planning or release-impact intelligence, depending on measured use—not another catalog expansion.

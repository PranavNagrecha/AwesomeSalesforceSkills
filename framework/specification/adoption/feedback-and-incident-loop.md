# Feedback and incident improvement loop

Classify every product defect into one primary system:

- input/target identity;
- host adapter;
- tool/upstream normalization;
- knowledge/source currency;
- context selection;
- product reasoning;
- evidence/claim link;
- reviewer/policy escape;
- output UX;
- QA/scenario gap.

For repeat or consequential defects, create:

1. minimized reproduction fixture;
2. expected required/forbidden finding facts;
3. deterministic test where possible;
4. context or evidence change;
5. reviewer rule if the defect was persuasive;
6. scenario/benchmark update;
7. changelog and affected requirement traceability.

Do not “fix” an evaluation by weakening labels to match output. Scenario truth changes require independent review and history.

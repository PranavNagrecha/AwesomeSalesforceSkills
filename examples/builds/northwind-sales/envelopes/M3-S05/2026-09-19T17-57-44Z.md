## 7. Process Observations

**Healthy**

- Every upstream fact was exact and needed no interpretation: the bundle name, its `lightning__RecordPage`
  target and the `discountThreshold` design attribute (`type` Integer, `default` 20) came verbatim from
  `artefacts/M3-S04/lwc/discountApprovalPanel/discountApprovalPanel.js-meta.xml`.
- The step's `notes` pre-recorded both traps this build type falls into — the missing `identifier`s in
  the path-and-guidance fence, and the non-recursive glob that forces the object file into this step —
  and both were exactly as described. Two discovery cycles became zero.
- Running `check_path_and_guidance.py` at build scope now returns *"Checked 2 path(s): no issues found"*
  where before this step it could only stay silent. This page is the first artefact in the build that
  makes that check assert anything at all.

**Concerning**

- `check_path_and_guidance.py` Check 6c indexes FlexiPage components **by `sobjectType`, not by record
  type**, so one Opportunity page carrying the component silences the note for *both* paths —
  `Renewal_Opportunity_Path` included, whose record type this build never assigns a page to. The green
  build-scope result therefore reads as closing **O-M2S05-04** when it does not.
- **No FlexiPage has ever been through an org anywhere in this library.** `examples/builds/` contains
  zero `*.flexipage-meta.xml`, and its one FlexiPage mention is a case-onboarding envelope recording
  that no FlexiPage was in scope for that step. Every Lightning-page shape this repo ships is
  fence-grounded; none is org-validated. That is precisely the gap the two `UNVERIFIED` markers sit in.
- `admin/lightning-record-page-configuration` ships no `## Questions to Ask Before Configuring` section
  (frontmatter `updated: 2026-08-15`, before the convention). Its `## Before Starting` block carries five
  genuinely question-shaped bullets and they were bound as such, but nothing in the file says they play
  that role.
- Two cited files disagree on the casing of the same two enum values, and the disagreement is documented
  rather than resolved: SKILL.md gives `view` / `flexipage`, `examples.md` and gotchas #1 give `View` /
  `Flexipage` — with gotchas #1 explaining why (*"the reference lists the enum values lower-cased;
  retrieved `.object-meta.xml` files carry them capitalised"*). The capitalised form was written, matching
  the fence, the plan's manual test, and the checker's case-insensitive comparison.

**Ambiguous**

- Whether `flexipage:recordHomeWithSubheaderTemplateDesktop` provides a region named **`sidebar`** is
  settled by no file in this repo. SKILL.md names header / main / sidebar as the slots templates define
  *in general*; the one fence for *this* template shows only `subheader` and `main`; the plan declares
  the sidebar placement. Written as declared, marked `UNVERIFIED`, and § 3.3 of the deploy-order note
  says how to settle it.
- The **`c:`** prefix for a custom LWC on a record page appears exactly once in the whole `skills/` tree

- Which Lightning apps expose Opportunity at Northwind was never asked. Assumption A38 records the gap.

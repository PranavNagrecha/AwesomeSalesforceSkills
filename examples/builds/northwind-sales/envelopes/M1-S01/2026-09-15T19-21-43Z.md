## 4. Decision record

The full sixteen-row table is in the envelope under `extensions.decision_record`. The four that
changed what got written:

1. **No stage carries `<default>true</default>`.** The org's existing default must survive the §0 merge
   untouched; moving the org-wide default stage would disturb the SMB record type that requirement item 6
   says must not break. The per-motion default lives on the `BusinessProcess` instead (Qualify, Renewal Review).
2. **No `picklistValues` block on either record type.** *(DEFAULT APPLIED — A5 for open Q40.)* StageName is
   governed by the business process, and a brand-new record type receives all current master values by default
   (`admin/picklist-and-value-sets` gotchas, Gotcha 5), so Approval_Status__c needs no block either.
3. **`Approval_Status__c` has no default value.** Q22 lists blank as a legal fourth state, set by the approval
   process; a default would put every new Opportunity into a status nobody submitted.
4. **`trackHistory` / `trackFeedHistory` are explicitly `false` on both fields.** No field history was requested
   and assumption A4 ships no `OpportunitySettings` file, so neither field depends on an object flag this build
   does not set.

`Commit` appears in no emitted file. Q5's sign-off word is written as the metadata token `Forecast`
(assumption A2, `admin/opportunity-management` gotchas Gotcha 13).

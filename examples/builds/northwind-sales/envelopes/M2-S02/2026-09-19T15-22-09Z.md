## 1. Summary

Repair pass on documented step `M2-S02` — `Enterprise_Sales_Record_Types` permission set + `Sales
User` profile overlay. Two fixes, both grounded and both landing clean on the first checker pass:

1. **Profile overlay:** removed both `recordTypeVisibilities` blocks from
   `profiles/Sales User.profile-meta.xml`. The org's validate-only run 1
   (`reports/MOCK-DEPLOY-M2.md`, 2026-09-19T14:56:10Z) refused the file with **N3-F-05**: *"No
   default record type specified for recordTypeVisibility: Opportunity. To make the '--master--'
   record type the default, set visible on all record types to false."* Naming a default among the
   two new types would move the SMB team's default Opportunity record type, violating Q4; making
   every listed type invisible would undo the step's purpose. The repair is neither: the block is
   dropped entirely. Visibility for `Opportunity.Enterprise` / `Opportunity.Renewal` is carried
   solely by the permission set (which has no `default` field to move), and the profile's silence
   leaves the org's existing default untouched — the same overlay mechanism the step's original
   design already rests on. `layoutAssignments` are byte-identical to what shipped in run 1.
2. **Permission set:** added two `fieldPermissions` blocks to
   `permissionsets/Enterprise_Sales_Record_Types.permissionset-meta.xml` —
   `Opportunity.Discount__c` (readable/editable) and `Opportunity.Approval_Status__c`
   (readable, not editable — the M3 approval process is the writer). This closes **HIGH open item
   O-M2S02-01** (`decisions.md` lines 677–699) by requester decision at this repair. No
   `objectPermissions` were added; Q19's existing Sales Cloud permission set is untouched. The
   set's `description` was revised to state the widened scope (195 characters).

Both fixes are recorded in a new **`artefacts/M2-S02/deploy-order.md` § 6 "Repair after run 1"**
(existing §§ 6–7 renumbered to §§ 7–8; no other section's text was changed). A library gap — no
cited skill or checker states the profile default-or-invisible-all rule the org just enforced — is
recorded as **PSVP-RT-DEFAULT-01** and left to the library, per this repair's explicit scope.

**Outcome: built.** `check-outputs` is ok; all four declared outputs still exist and nothing else
was written.

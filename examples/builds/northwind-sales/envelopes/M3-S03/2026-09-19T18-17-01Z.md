## Summary

Repaired M3-S03's test fixture for **N3-F-08**, the object-level twin of scenario-1's
field-level Gotcha 15 finding. Per `reports/MOCK-DEPLOY-M3.md` run 4
(2026-09-19T18:10:13Z), all six `OpportunityApprovalServiceTest` methods threw
`System.QueryException: sObject type 'Opportunity' is not supported` at
`OpportunityApprovalService.submitBatch` line 79 — the service's `WITH USER_MODE` SOQL,
inside `System.runAs(<persona>)`. Root cause: the persona (profile `Sales User` +
`Enterprise_Sales_Record_Types`, which by design grants record types and two field
permissions and no object permissions) has no Opportunity object permission in
`sfskills-dev`. Q19 assumed the org's existing Sales Cloud permission set would supply
object CRUD; that set is not in this build and not in the validating org.

**Requester decision implemented:** the test now seeds the grant the code under test
needs. `seedFixture` inserts a test-scoped `PermissionSet` (`Test_Opportunity_Access`,
label `Test Opportunity Access`) plus one `ObjectPermissions` row on `Opportunity`
(`PermissionsRead`/`PermissionsCreate`/`PermissionsEdit` true, `PermissionsViewAllRecords`
false), and assigns it to both the manager and the rep alongside
`Enterprise_Sales_Record_Types` — inside the same self-user mixed-DML fence the fixture
already uses for the `User` and `PermissionSetAssignment` inserts, because `PermissionSet`
and `ObjectPermissions` are both setup objects (`apex/mixed-dml-and-setup-objects`).
`FieldPermissions` rows for `Name`/`StageName`/`CloseDate`/`Amount` are deliberately
withheld — added only if the org refuses again on FLS, per the requester's instruction not
to pre-empt that finding.

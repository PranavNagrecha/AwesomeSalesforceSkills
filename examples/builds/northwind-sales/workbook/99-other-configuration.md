# Configuration Workbook — Other configuration

Per-step slice, written by the build doc keeper after `M1-S01` was tested.

**Why these two rows are here and not in a numbered section.**
`agents/build-doc-keeper/AGENT.md` Step 4 routes `package.xml` and the deploy-order note to
"10 — Data + Migration only when they are a migration artefact, otherwise to **Other
configuration**". Neither is a migration artefact — `M1-S01` loads no data — so they land in the
default section. The step's own **type** (`object-model`) is in Step 4's map and produced the seven
Section 1 rows in `workbook/01-objects-and-fields.md`; this is the artefact-level default the same
paragraph defines, not the unmapped-step-type case.

**One thing a reader should know about this file.** `check_workbook.py` recognises a section only
from a heading matching `^#{2,3}\s+Section\s+(\d+)\s*[—-]\s*(.+)$`, so rows under the heading
**Other configuration** are parsed into no section and are invisible to that linter. Numbering it
"Section 11" would make it visible and would also invent an eleventh canonical section, which
`skills/admin/configuration-workbook-authoring` Concept 2 forbids ("The workbook is fixed at ten
sections. Authors do not invent new sections"). The heading is left as the AGENT.md specifies and
the linter gap is reported instead. `source_req_id` below uses `;` rather than `\|` to delimit
multiple requirement ids in one cell — `check_workbook.py` splits a row on every bare `|` with no
escape handling, so a literal `\|` would shift every later column the moment this file is ever read
under a recognised section heading (it is not, today, but the compile run at `M4-S03` assembles
every per-step slice into one document that is).

migration artefacts, so per `agents/build-doc-keeper/AGENT.md` Step 4 they land here instead. Same
`;`-delimited multi-value convention as the two rows below.

**Six more rows were added after `M2-S02`, `M2-S03` and `M2-S05` (`CWB-OTHER-005`–`010`).** Same
routing rule: each step's own artefacts produced rows in `workbook/03-profiles-permission-sets-and-psgs.md`
(`M2-S02`), `workbook/05-validation-rules.md` (`M2-S03`) and `workbook/02-page-layouts-and-lightning-pages.md`
(`M2-S05`); none of the three steps' `package.xml` or `deploy-order.md` is a migration artefact, so
all six land here.

**Two more rows were added after `M2-S04` (`CWB-OTHER-011`–`012`).** Same routing rule: `M2-S04`'s
own artefact produced a row in `workbook/05-validation-rules.md`; its `package.xml` and
`deploy-order.md` are not migration artefacts, so both land here.

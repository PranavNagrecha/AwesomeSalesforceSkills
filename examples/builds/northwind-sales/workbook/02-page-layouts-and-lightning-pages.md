# Configuration Workbook — Section 2

Per-step slice, written by the build doc keeper after `M1-S02` was tested. This build is
`build_mode: design-only`, so per `standards/build-orchestration.md` § 4 every `ui` step routes to
`metadata-builder`; `recommended_agent` below names the step's owning agent (`metadata-builder`),
not the Section 2 default (`audit-router --domain=lightning_record_page`, which audits an existing
Lightning record page in a live org), per `agents/build-doc-keeper/AGENT.md` Step 4.

Row schema and section list: `skills/admin/configuration-workbook-authoring` SKILL.md Concepts 1–3.
`REQ-008` through `REQ-010` are minted in this run, continuing from `REQ-001`–`REQ-007`
(`M1-S01`, `workbook/01-objects-and-fields.md`). `REQ-008` and `REQ-009` are the two layouts
themselves; `REQ-010` is minted for the Opportunity Products related-list half of `requirement.md`
item 2 and is **not satisfied** by this step's artefacts — see its row in `traceability.md` and
`decisions.md` **O-M1S02-01**. Multi-value cells use `;`, the same convention
`workbook/99-other-configuration.md` uses, because `check_workbook.py` splits a row on every bare
`|` with no escape handling.

**One thing a reader should know about these two rows.** Neither layout is assigned to anyone yet.
`layoutAssignments` lives only on `Profile`, never on `PermissionSet`
(`admin/record-types-and-page-layouts/references/metadata-examples.md`, "Making the record type
visible and assigning the page"), and the profile work is `M2-S02`'s, human-gated. Both layouts
deploy and neither is reachable by a user until `M2-S02` lands — the same shape `decisions.md`
**O-M1S01-03** already records for the two record types this step's layouts serve.

**Three more rows were added after `M2-S05` (`CWB-PATH-001`–`003`).** `REQ-016` through `REQ-018`
are minted in this run, continuing from `REQ-001`–`REQ-015`. `REQ-016` and `REQ-017` are the
Enterprise and Renewal Opportunity Paths themselves; `REQ-018` is the org's `PathAssistant`
preference, a supporting artefact for both rather than a layout of its own, so it carries both
requirement ids instead of minting a third. **A green deploy of any of these three rows proves
neither that Path is enabled in the org (edition-dependent — assumption A12) nor that the Path
component is on a Lightning record page** (`M3-S05`, pending, rebuilds the Enterprise page only) —
`artefacts/M2-S05/deploy-order.md` § 3, `decisions.md` **O-M2S05-04**.

## Scope

### In scope
- Block any Opportunity save that lowers Amount once `StageName = Closed Won`; Amount is typed directly, no Products/Line Items roll up into it (Q1).
- Sales-Ops-only correction path via a named Custom Permission on a dedicated Permission Set, not a Profile exemption (Q3).
- Deploy the rule `active=true` using a delta check so it fires only on a further decrease and does not retroactively re-block the historical violations left as-is (Q5).
- Error message fixed to the Q4 default text, attached to the Amount field, on the standard layout(s) in scope (Q4, Q8 default).

### Out of scope
- Cleaning up the historical Closed Won Opportunities whose Amount was already lowered (Q5 declines data clean-up; carried via the delta-check design).
- A record-triggered flow or Apex path for Amount — Amount is edited directly, no line-item rollup exists (Q1).
- Any bypass or contract change for an external system — no ERP/CPQ/billing system writes Amount (Q7).
- Any change to the Opportunity sharing or field-level-security model (Q11 default, A4).
- A new report or dashboard counting blocked saves (Q13 default, A6).

`llm-anti-patterns.md` disagreed, and the headline file was the wrong one.

```

  NOT($Permission.Bypass_Opp_Amount_Lock),

  NOT(ISBLANK(TEXT(StageName))),

```

| Clause | Position | Grounded in |
|---|---|---|
| `AND(...)`, bypass → relevance → business rule | — | `templates/admin/validation-rule-patterns.md`, "The canonical VR shape" |
| `NOT($Permission.Bypass_Opp_Amount_Lock)` | 1 — bypass | `admin/validation-rules/SKILL.md` Bypass-patterns table: Custom Permission is *"Preferred — granular, auditable"*; identical consumer snippet at `admin/custom-permissions/references/metadata-examples.md` § 6 |
| `NOT(ISNEW())` | 2 — relevance | `admin/validation-rules/references/gotchas.md`, "PRIORVALUE Does Not Work on Insert" — its GOOD example puts `NOT(ISNEW())` first inside the `AND` |
| `NOT(ISBLANK(TEXT(StageName)))` | 3 — relevance | `admin/validation-rules/references/llm-anti-patterns.md` Anti-Pattern 6, "With null handling" — `NOT(ISBLANK(TEXT(Status)))`, same shape. Confirmed compiling by the operator probe at API 67.0 |
| `ISPICKVAL(StageName, "Closed Won")` | 4 — relevance | `admin/validation-rules/references/metadata-examples.md` Example 1 rule 1 — same field, same literal, double-quoted |
| `Amount &lt; PRIORVALUE(Amount)` | 5 — business rule | `templates/admin/validation-rule-patterns.md`: *"`PRIORVALUE(Field)` — the value at the start of the save context. Use for 'cannot regress' rules."* `&lt;` per W7 and the skill's *"a bare `<` … makes the file invalid XML and the deploy fails at parse time with no rule-level error"* |

Escaping: `&` → `&amp;` then `<` → `&lt;`. The only character needing it is the `<` in clause 5.

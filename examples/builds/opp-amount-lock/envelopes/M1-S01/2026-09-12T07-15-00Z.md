## Divergence from `plan.json` — read this before accepting the step

| | Formula |
|---|---|
| `plan.json.steps[].inputs.errorConditionFormula` | `AND(NOT($Permission…), NOT(ISNEW()), **NOT(ISBLANK(StageName))**, ISPICKVAL(StageName,"Closed Won"), Amount < PRIORVALUE(Amount))` |
| Built | the same, **without** the `NOT(ISBLANK(StageName))` clause |

**Why.** The invoking instruction specified this four-clause formula. It also resolves verification warning
**W4**, which records that `admin/validation-rules` contradicts itself on `ISBLANK` over a picklist and offers
`NOT(ISBLANK(TEXT(StageName)))` as the reconciliation if the platform rejects a raw picklist argument.

**Syntax note.** The instruction wrote the clauses joined with `&&` and the literal as `'Closed Won'`. Both
were rendered as `AND(…)` with double quotes instead: `AND(…)` is the canonical shape in the template and in
every example in the skill, and single-quoted literals appear in this skill only inside
`references/llm-anti-patterns.md` Anti-Pattern 2 as *what an LLM generates wrong*. The clause set and their
order are exactly as instructed.

**What it costs.** `check_validation_rules.py` line 418 raises `REVIEW … picklist logic has no explicit blank
guard` when a formula contains `ISPICKVAL(` and no `ISBLANK(`. `REVIEW` carries severity weight 0 and is not
in `BLOCKING_SEVERITIES`, so the checker still exits 0 — but the run now prints **2 findings** where the step's
acceptance-test `description` records *"WARN: 1 finding(s) detected (0 blocking)"*. `expected: exit 0` holds;
the description no longer matches byte for byte.

**What it contradicts.** `admin/validation-rules/SKILL.md` § Formula Best Practices opens *"Always guard
picklist checks against blank"* and gives the exact counter-example
`AND(NOT(ISBLANK(StageName)), ISPICKVAL(StageName, "Closed Won"))`. This artefact does not carry that guard.

**Why it is nonetheless safe here.** `ISPICKVAL(StageName, "Closed Won")` returns FALSE when `StageName` is
blank, so the *positive* form cannot misfire on a blank picklist — the skill's warning is aimed at the
`NOT(ISPICKVAL(…))` form. `StageName` is a required standard picklist on Opportunity and cannot be blank on a
saved record in any case.

**Three remedies, the human's choice.** (1) accept as built; (2) restore the guard as
`NOT(ISBLANK(TEXT(StageName)))` — valid on a picklist, silences the REVIEW, restores the clause count;
(3) restore the plan's literal `NOT(ISBLANK(StageName))` — matches `plan.json` but is the form W4 flags.
Either restoration needs `build_plan.py amend-step` to bring `plan.json` back into sync; **neither this agent
nor `build-step-runner` is authorised to run it.**

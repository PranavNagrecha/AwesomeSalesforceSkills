## 10. Process Observations

### What was healthy

- **[info · library-depth]** Both closable defects this round were closed by library repairs rather than by plan workarounds. check_case_management_setup.py grew recursive discovery and inner-element rule reads this session, which turned M3's milestone case-management sweep from a scoped-out impossibility into a declarable test and gave M3-S04 its first checker. check_validation_rules.py's severity model, which the v4 plan got backwards, turned out to have the exact flag the step needed. A plan that had worked around either would have shipped a weaker test surface than the library could support.

### What was concerning

- **[medium · test-surface]** A repaired checker leaves stale prose behind, and the stale prose is worse than the original defect. Fixing W02 meant checking every passage in the plan that asserted the pre-repair behaviour, and there were three beyond the step the verifier named: M3's milestone acceptance_tests[4] was a manual test whose whole content was the false claim, M3-S04's note used it to justify declaring no checker, and scope.out[20] used it to scope the sweep out. Each would have read at G2 as a documented library limitation rather than as a sentence nobody re-checked. The lesson generalises: when a checker changes, grep the plan for the claim, not for the step id.
- **[medium · test-surface]** Two of the six v4 findings were the same failure: a test description written from the checker's name rather than from a run. W01's 'returns 1 on ANY finding' and W02's non-recursive discovery both survived three verification rounds because the descriptions sounded right and the exit codes happened to agree on the fixtures anyone tried. The nine invocations re-run this round were run before anything was declared, and two of them changed what got written. Fixture-first is not a nicety in this loop; it is the only thing that separates a description from a guess.
- **[medium · test-surface]** Three validate WARNs remain and all three are the contract's own documented follow-up: check_sandbox_plan.py takes a positional path, check_workbook.py takes --workbook, check_ac_format.py takes --file. Unchanged from v4 and correct rather than worked around — declaring --manifest-dir on any of the three would name a flag its parser does not define, which step-tester runs verbatim and which exits on a usage error that reads as a failing step.

### What was ambiguous

- **[low · access-model]** Flipping M1-S01's human_gate to true is the one v5 change to a step the v4 verification passed, and it could reasonably have gone the other way. The step is type object-model, not access, and a Private OWD restricts rather than broadens. But Step 6's list of gate triggers names org-wide defaults categorically, and an OWD landing inside an ungated step is the shape that rule exists to catch. It was flipped, and the reasoning is written into the step note so a reviewer can overturn it deliberately rather than notice it late.
- **[low · test-surface]** check_case_management_setup.py is now declared three times at --manifest-dir artefacts — on M3-S03, on M3-S04 and as M3's milestone test. That is defensible (each runs at a different point in the milestone, so M3-S03's runs before the rules exist, M3-S04's after, and the milestone's once every step is documented) but it is also three identical commands, and a reader could reasonably call two of them redundant. The alternative — one milestone test only — would leave M3-S04 with no checker at all, which is what v4 had and what the false note justified.
- **[low · scope]** Dropping settings/Sharing.settings-meta.xml rather than keeping it went beyond the verifier's own wording, which said M2-S05 'keeps … the settings file if the org-level sharing switches are wanted'. Nothing in the requirement or the answers asks for an org-level sharing switch, and neither cited skill documents the file, so keeping it would have declared an output nothing grounds and nothing reads. If a later answer does ask for one, it is a new output on this step and a new manifest member, not a re-plan.

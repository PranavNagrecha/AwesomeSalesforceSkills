## 2. The headline finding — the report does not yet answer Q91

`artefacts/M4-S04/escalation-monitoring-note.md` § 2 specifies `Escalated = True` AND
`Closed = False` AND `Date/Time Opened = LAST 30 DAYS`. The **Escalated** criterion is not in the
file: report column codes are report-type specific, `skills/admin/reports-and-dashboards` instructs
retrieving an existing report rather than deriving them, and no file in the library carries a code
for `Case.IsEscalated`. Inventing one is refused by AGENT.md Step 5 rule 1.

As written, the report returns **open Cases from the last 30 days**, not **escalated** open Cases —
it over-reports, silently. The remedy is one retrieve plus one `criteriaItems` block and a
`booleanFilter` change to `1 AND 2 AND 3`; it is written out in `deploy-order.md` § 2 U1, carried
in an XML comment above the filter in the report file itself, and repeated in the report's
`<description>` so a reader in Setup sees it too.

`Status = Escalated` is **not** a substitute: the Case status ladder does carry an `Escalated`
value, and `M4-S04`'s note is explicit that the `IsEscalated` checkbox is the signal being
monitored.

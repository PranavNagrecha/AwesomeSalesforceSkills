does not list `ReportFolder` as a type with no standalone source file — it has a file here, just a

run read the file's content: a `<ReportFolder>` root element naming `Support Operations`, matching

basis the file<->member correspondence was judged consistent. This is a structural read, not a
re-verification of the checker's own recognition logic — the checker-recognition gap (finding F-B /
U-item in the prior envelopes) stands independently and is unaffected by this judgment.

## Why this rebuild happened

`reports/MOCK-DEPLOY-M1.md` finding **F-11** (HIGH): `sf project deploy start --dry-run` rejected
this step's business processes in source format. Each `*.businessProcess-meta.xml` carried a spaced
`<fullName>` (`Support Process`) while the CLI names the package member from the **file stem**
(`Support_Process`), so the member resolved to nothing:

```
An object 'Case.Support_Process' of type BusinessProcess was named in package.xml,
but was not found in zipped directory
```

The rule is now library content rather than a report footnote. `admin/case-management-setup` v1.2.0
states it in `references/metadata-examples.md` § 2.1 and enforces it as **CMS-STEM-01** (file stem
must equal `<fullName>`; no spaces in `<fullName>`) and **CMS-STEM-02** (a record type's
`<businessProcess>` must name an existing process file stem).

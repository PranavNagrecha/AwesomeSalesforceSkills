Rebuild #2 of M2-S02 (access step: permission sets and permission set groups for Tier 1,
Tier 2 and Billing), triggered by `reports/MOCK-DEPLOY-M2.md` run 1 finding **F-15**: the org
rejected all four `PermissionSet` files with `Description: data value too large … (max
length=255)`, and the three `PermissionSetGroup` files cascaded (`permission set names are
invalid`) as a consequence. Rewrote only the `<description>` element of

`Case_Tier1.permissionset-meta.xml` and `Case_Tier2.permissionset-meta.xml` to 192 / 183 / 193
/ 199 characters respectively — all ≤200, clearing both the 255-char ERROR and the 200-char
WARN. The trimmed rationale moved into `deploy-order.md` under "Rebuild #2 — descriptions".
No PSG file needed editing: all three `PermissionSetGroup` descriptions (187 / 194 / 132
chars) were already under 200. Every non-description element of the four permission sets is
byte-identical to the first pass. All three cited skills' checkers plus `check-outputs` exit 0
with no DESC finding on any M2-S02 file.

ceiling that produced F-15, with a 200-char WARN as headroom — a description-length defect of
this shape cannot reach a mock deploy again for these three skills. (Source: the three checker

pre-existing WARN on `M2-S01/permissionsets/Case_Intake_Integration.permissionset-meta.xml`
(244 chars) — that step passed the first mock deploy by luck under the old checker and is now
flagged, though it is out of this step's scope to fix. (Source: post-edit build-scope run.)

against the `Profile.description` limit the deploy report also names (F-15 covers Profile too,

still carries a long description and no length rule would reproduce this exact deploy-time
failure for that metadata type. (Source: `reports/MOCK-DEPLOY-M2.md` run 1.)

restated here because a description edit is exactly where it could have been silently
resolved and was not: Q13 (Support record type for Billing) remains DEFERRED; `Case_Billing`
keeps the conservative reading (assumption A1). (Source: `artefacts/M2-S02/deploy-order.md`,
"Decisions worth reading before deploy" item 6.)

## 4. Blocker

### B01 — `M2-S05` · grounding + testability

**Problem.** The Case org-wide default has no artefact that can carry it. `outputs[]` declares
`artefacts/M2-S05/settings/Sharing.settings-meta.xml`, and `acceptance_tests[3]` asserts that "when
`settings/Sharing.settings-meta.xml` and `sharingRules/Case.sharingRules-meta.xml` are read together, then
the Case org-wide default is Private". The cited skill states the opposite, and the checker declared on the
step cannot read that file at all.

**Evidence.**

- `skills/admin/sharing-and-visibility/references/metadata-examples.md:11` — "`sharingModel` is the internal
  org-wide default; `externalSharingModel` is the one for external users. **Both live on the `CustomObject`
  file, not in a separate settings file.**"
- `check_sharing_model.py:39-45` — `SUFFIXES` is `.object-meta.xml`, `.profile-meta.xml`,
  `.permissionset-meta.xml`, `.sharingRules-meta.xml`, `.role-meta.xml`. No `.settings-meta.xml`.
  `collect_sharing_models` (:161-177) resolves an OWD only from a `CustomObject` file's `<sharingModel>`.
- `grep -c sharingModel .sfskills/builds/case-onboarding/plan.json` → **0**. No step declares it anywhere.
- Fixture at the step's declared paths: `Scanned 1 sharing-model metadata file(s) (0 object OWD(s)
  resolved); 0 finding(s) detected.` exit 0.
- Same command at the M2 milestone test's scope (`--manifest-dir artefacts`): `Scanned 10 sharing-model
  metadata file(s) (0 object OWD(s) resolved)`, exit 0.
- **Remedy proof.** With `<sharingModel>Private</sharingModel>` added to `objects/Case/Case.object-meta.xml`:
  `(1 object OWD(s) resolved); 0 finding(s) detected.` exit 0. With the same element set to `ReadWrite`:
  exit **1**, `HIGH … criteria-based rule 'Support_Cases_To_Tier_2' grants 'Edit' but 'Case' has
  sharingModel 'ReadWrite' - the grant is not above the object's default, so it adds no access`.

**Why it is a blocker rather than a warning.** As declared, `metadata-builder` writes a `SharingSettings`
file that cannot set the Case OWD, and both tests that claim to assert the OWD exit 0 on any value.
Decision D5, the M2 milestone goal "a Tier 1 agent cannot open a Billing case", and the fit-gap row
"Finance queries worked only by Finance" all rest on `Private`.

**Fix.** Declare `<sharingModel>Private</sharingModel>` and `<externalSharingModel>Private</externalSharingModel>`
on `objects/Case/Case.object-meta.xml` — M1-S01's output — add `M1-S01` to M2-S05's `depends_on`, and reword
`acceptance_tests[3]` to read the OWD from the object file. M2-S05 keeps the sharing rule, the settings file
if the org-level sharing switches are wanted, and the visibility note.

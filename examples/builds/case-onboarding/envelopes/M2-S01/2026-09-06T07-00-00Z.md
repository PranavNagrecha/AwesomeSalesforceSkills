## 7. Deploy-order note

Reproduced in full at `artefacts/M2-S01/deploy-order.md`. The three things a reader needs from it:

1. **`CustomPermission` before `PermissionSet`** — a permission set naming a permission that does not exist fails the deploy.
2. **This step deploys before M3-S01, and that ordering is load-bearing.** A validation rule whose `$Permission.X` names a missing permission does not fail the deploy; it evaluates `false` silently (gotcha 4), so every API-created Case would be blocked from the moment M3-S01 landed until this step landed.
3. **A post-deploy assignment the deploy does not perform** — `PermissionSetAssignment` is record data. `Case_Intake_Integration` goes to the Email-to-Case / Web-to-Case automated-process identity only, never to a human, owner: Security architect, evidence by `SetupEntityAccess` query rather than a metadata diff.

The validate-only commands are text for a human; this agent ran neither. Both forms are given, matched to their target — `sf project deploy start --dry-run` for a sandbox (closing M1 finding **F-08**) and `sf project deploy validate --test-level RunLocalTests` for production.

## Summary

Repair (run 3) of step M1-S02 after the whole-build mock deploy (run 8) found
`EventBus.publish` of `Tier2_Escalation__e` denied for the Standard User running
`Tier2EscalationServiceTest.ownerChangeToTier2QueueEscalatesAndStamps`: at API 67.0,
`EventBus.publish` runs in user mode and needs Create on the event object, and no
permission set this build ships granted anything on `Tier2_Escalation__e`.

**Fix:** one new `objectPermissions` row added to the existing `Tier2_Webhook_Admin`
permission set — `allowCreate` and `allowRead` true on `Tier2_Escalation__e`,
`allowEdit`/`allowDelete`/`viewAllRecords`/`modifyAllRecords` false — rather than a new
permission set, because the publishing population is exactly decision **D14**'s existing
assignee set (the user whose Case save moved ownership to `Tier_2_Engineering`, the same
async-context user the Named Credential principal access and `Integration_Failure__c`
CRUD in this same set already serve in the same transaction, per decision **D10**).

`description` updated to name the new grant; `deploy-order.md` gained § 0b (finding, root
cause, the set-vs-new-set decision and its rejected alternative), a § 4 decisions-table
row, and a § 6 clause (g). No new component: `package.xml` and the External Credential /
Named Credential files are unchanged, so `M1-S05`'s build-level manifest needs no change.

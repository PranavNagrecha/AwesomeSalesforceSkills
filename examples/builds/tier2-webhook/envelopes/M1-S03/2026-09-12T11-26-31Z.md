## 7. Where AGENT.md and the CLI did not support § 3.1 at `feature`

1. **`templates[]` is validated for existence, never for what the template needs.** It cost
   this build two refusals across its two Apex steps. A plan-time check that greps each cited
   `templates/apex/**` file for other template class names and for `__c` / `__mdt` tokens,
   warning when the closure is not covered by some step's `outputs[]`, would have caught both
   before any builder ran.
2. **A step's `outputs[]` cannot be corrected once it leaves `pending`.** So the template
   copies the provenance rule obliges the agent to ship stay permanently undeclared and
   permanently unverified by `check-outputs`. Either the planner declares template copies up
   front, or § 4's Apex-foundations step owns them in one place — and the `feature` tier's
   five-step ceiling, which carves out only the manifest step, is what discourages the latter.
3. **The persistence contracts still disagree.** Wave 10 names a
   `docs/reports/build-step-runner/` pair alongside the build-scoped envelope; § 2 puts agent
   envelopes under `envelopes/<step-id>/`. The invocation constrained writes to the build
   directory, so only the build-scoped pair was written. Unchanged from run 1, and unresolved.

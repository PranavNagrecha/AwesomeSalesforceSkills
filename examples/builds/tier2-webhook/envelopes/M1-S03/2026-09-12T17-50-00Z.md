## Root cause

Run 6's file header assumed that omitting `Test.startTest()`/`Test.stopTest()` around a
direct `Tier2WebhookFinalizer.execute(ctx)` call would stop the Finalizer's own
re-enqueued `Tier2WebhookQueueable` from ever running inside the test. **The org's real
execution disproves that** — the re-enqueued job still runs to completion by the end of
the enclosing test method. In the failing method, the original call is `attempt = 1`, so
the re-enqueued job lands at `attempt = 2` — still below `MAX_ATTEMPTS` (3). No
`Test.setMock()` was registered anywhere in the method, so the re-enqueued job's callout
threw `CalloutException`, was classified transient, and — still below the ceiling —
re-threw `Tier2WebhookQueueable`'s own transient-retry exception, uncaught this time.

**Why the sibling method didn't also fail:** `secondConsecutiveFailureUpdatesTheExistingRowRatherThanInsertingASecond`
calls `execute(ctx)` with `attempt = 2`, so *its* re-enqueued job lands at `attempt = 3 =
MAX_ATTEMPTS`. When that job's callout also fails unmocked, `attempt < MAX_ATTEMPTS` is
now false, so the Queueable falls into `persistOutcomes`'s no-retry branch instead of
re-throwing — no uncaught exception, no failure, but the same unmocked-callout condition,
surviving only by ceiling arithmetic (flagged as S7-F-03, not fixed — nothing there is
broken).

## The fix

**Chosen: register a 2xx mock before the call, not "assert without forcing execution."**
The second option was ruled out by the org's own result: the job runs regardless of how
the call is wrapped, so there is no way, in this environment, to avoid the platform
eventually running whatever the Finalizer re-enqueues. Given that, the only lever
`skills/apex/callouts-and-http-integrations` and `skills/apex/apex-mocking-and-stubs` both
already prescribe is a registered mock, so the callout succeeds instead of throwing.

# Learning Brief Gotchas

## Beginner-friendly can become fact-hostile

Removing release, permission, transaction, or scale qualifiers can make a lesson easier to read and wrong to apply. Simplify vocabulary and branching, not the load-bearing boundary.

## A citation list is not citation mapping

A list of ten sources at the end does not show which source supports a numeric limit or lifecycle date. Keep claim IDs or nearby citations.

## Procedures decay faster than concepts

UI navigation and CLI flags change more often than mental models. Date procedures, identify the tool major version, and emphasize verification commands or authoritative reference pages.

## Examples are sticky

Learners often reuse illustrative names and patterns as prescriptions. Label scenario assumptions and explain what would change the approach.

## Knowledge checks can test the wrong thing

Avoid questions that merely repeat a definition. Change a constraint, ask for evidence, or ask the learner to distinguish guarantee from recommendation.

## Practice tasks can create authority risk

A teaching exercise must identify a safe environment and stop condition. Do not send a beginner to modify production permissions or data to demonstrate understanding.

## Learning objectives can hide adjacent scope

"Understand sharing" is too broad for one brief. Bound the outcome—for example, distinguish object permissions, field permissions, and record access for one persona.

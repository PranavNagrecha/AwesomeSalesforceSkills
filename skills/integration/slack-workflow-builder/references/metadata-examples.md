# Metadata Examples: Autolaunched Flow for Run a Flow, and the Coded Equivalent

A deployable autolaunched flow that the Slack Workflow Builder **Run a Flow** step can call, plus a coded Slack workflow (Deno Slack SDK) that calls the same flow through the Salesforce connector. Flow element names come from the Metadata API Developer Guide, Version 67.0 (Flow, FlowRecordCreate, FlowVariable, FlowStart). Connector inputs and outputs come from Slack's autogenerated connector schema (`slackapi/deno-slack-hub`, `src/connectors/salesforce/functions/run_flow.ts`).

## File: `force-app/main/default/flows/AL_Slack_Log_Follow_Up.flow-meta.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Flow xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>67.0</apiVersion>
    <description>Called by the Slack Workflow Builder Run a Flow step to log a follow-up task on an Opportunity.</description>
    <interviewLabel>AL Slack Log Follow Up {!$Flow.CurrentDateTime}</interviewLabel>
    <label>AL Slack Log Follow Up</label>
    <processType>AutoLaunchedFlow</processType>
    <recordCreates>
        <name>Create_Follow_Up_Task</name>
        <label>Create Follow Up Task</label>
        <locationX>176</locationX>
        <locationY>158</locationY>
        <assignRecordIdToReference>taskId</assignRecordIdToReference>
        <inputAssignments>
            <field>Subject</field>
            <value>
                <elementReference>taskSubject</elementReference>
            </value>
        </inputAssignments>
        <inputAssignments>
            <field>WhatId</field>
            <value>
                <elementReference>opportunityId</elementReference>
            </value>
        </inputAssignments>
        <object>Task</object>
    </recordCreates>
    <start>
        <locationX>50</locationX>
        <locationY>0</locationY>
        <connector>
            <targetReference>Create_Follow_Up_Task</targetReference>
        </connector>
    </start>
    <status>Active</status>
    <variables>
        <name>opportunityId</name>
        <dataType>String</dataType>
        <isCollection>false</isCollection>
        <isInput>true</isInput>
        <isOutput>false</isOutput>
    </variables>
    <variables>
        <name>taskId</name>
        <dataType>String</dataType>
        <isCollection>false</isCollection>
        <isInput>false</isInput>
        <isOutput>true</isOutput>
    </variables>
    <variables>
        <name>taskSubject</name>
        <dataType>String</dataType>
        <isCollection>false</isCollection>
        <isInput>true</isInput>
        <isOutput>false</isOutput>
    </variables>
</Flow>
```

| Element | Why |
|---|---|
| `processType` `AutoLaunchedFlow` | The connector accepts auto-launched flows only |
| `status` `Active` | Inactive flows fail when the step runs |
| `isInput` on `opportunityId`, `taskSubject` | These become the Run a Flow step's inputs |
| `isOutput` on `taskId` | Returned in the step's `result` for the confirmation message |

UNVERIFIED (2026-10-03): that only variables marked `isInput` appear as step inputs is stated in the Salesforce Admins blog ("variables marked Available for input") rather than a product guide. Flow element order follows retrieved files; if a deploy rejects the order, retrieve a flow built in Flow Builder and match it.

## File (Slack app): `workflows/log_follow_up.ts`

```typescript
import { DefineWorkflow, Schema } from "deno-slack-sdk/mod.ts";
import { Connectors } from "deno-slack-hub/mod.ts";

export const LogFollowUpWorkflow = DefineWorkflow({
  callback_id: "log_follow_up",
  title: "Log a Salesforce follow-up",
  input_parameters: {
    properties: {
      interactivity: { type: Schema.slack.types.interactivity },
      channel_id: { type: Schema.slack.types.channel_id },
      opportunity_id: { type: Schema.types.string },
      task_subject: { type: Schema.types.string },
    },
    required: ["interactivity", "channel_id", "opportunity_id", "task_subject"],
  },
});

const runFlow = LogFollowUpWorkflow.addStep(Connectors.Salesforce.functions.RunFlow, {
  flow_name: "AL_Slack_Log_Follow_Up",
  metadata: {
    opportunityId: LogFollowUpWorkflow.inputs.opportunity_id,
    taskSubject: LogFollowUpWorkflow.inputs.task_subject,
  },
  // Each person authenticates their own Salesforce account; requires a link trigger.
  salesforce_access_token: { credential_source: "END_USER" },
});

LogFollowUpWorkflow.addStep(Schema.slack.functions.SendMessage, {
  channel_id: LogFollowUpWorkflow.inputs.channel_id,
  message: `Follow-up logged in Salesforce (flow ${runFlow.outputs.flow_name}).`,
});

export default LogFollowUpWorkflow;
```

- `Connectors.Salesforce.functions.RunFlow` requires `flow_name` and `salesforce_access_token`; it returns `success`, `flow_name`, and `result`.
- `credential_source: "END_USER"` makes each person authenticate and "can only be started by a Link Trigger"; `"DEVELOPER"` uses a collaborator's account selected with `slack external-auth select-auth`.

UNVERIFIED (2026-10-03): the schema types `metadata` as an object titled "Name" and does not document its keys, so passing flow inputs through `metadata` keyed by variable name is an assumption to confirm in a sandbox. The no-code Workflow Builder maps inputs in the step UI and needs no code.

# Learning Research Gotchas

## Search-result text is not a source

Snippets can be stale, truncated, or synthesized. Open the page, check context and date, and record the page—not the snippet—as evidence.

## A Salesforce-owned blog is not always the behavior contract

Official blogs are excellent for explanation and release highlights. Use product documentation or release notes for exact behavior, limits, lifecycle, and command options when available.

## Trailhead intentionally simplifies

Trailhead can define the learning sequence but may omit exceptions and version gates. Verify exact platform behavior before turning a simplified module statement into a hard rule.

## Documentation cannot inspect the learner's org

A capability can be generally available yet absent because of edition, add-on, feature activation, namespace, package version, user permission, or release timing. Mark target state unknown unless evidence identifies it.

## Current and preview content can share a page

A page may discuss GA, beta, and preview features together. Tag each claim independently; do not assign the page's broad release label to every feature.

## Product renames create false contradictions

Check aliases, predecessor products, acquired products, and release-era names before concluding that two sources disagree.

## Publication date is not applicability

An old API contract can still be current; a recent blog can describe a limited preview. Record both source date and feature applicability.

## Self-referential evidence loops

Do not cite an SfSkills summary as the authority for a claim that the new lesson then uses to validate the same SfSkills summary. Inspect the underlying official source.

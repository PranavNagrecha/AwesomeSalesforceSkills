## 3. A FACT I GOT WRONG TWICE — do not re-introduce it

I instructed several waves that *"Apex triggers always run in system mode at
every API version and cannot declare sharing or access modes."* Wrong. I then
"corrected" it to **"two independent axes"**. Also wrong. Verifiers caught both,
5 blockers on the second.

**Ground truth**, `apex_classes_keywords_sharing.htm`, verbatim:

> "Apex triggers can't have an explicit sharing declaration. Triggers always run
> implicitly in a without sharing context."

> "However, database operations within trigger bodies, including SOQL queries,
> SOSL queries, DML statements, and Database methods, run in **user mode** unless
> system mode is explicitly specified."

> "**User mode overrides the trigger's without sharing context** and effectively
> enforces a with sharing context in the trigger body."

So the correct model is **declaration vs outcome, not two independent axes**:
- the sharing DECLARATION is fixed and undeclarable;
- what the body ENFORCES follows each operation's access mode;
- at 67.0+ a bare trigger query enforces sharing **and** FLS **and** CRUD;
- only an explicit `WITH SYSTEM_MODE` falls back to bypassing all three
  (the docs ship a worked `WITH SYSTEM_MODE`-inside-a-trigger example).

The dangerous version reached a checker's runtime output and an
`llm-anti-patterns.md` — the two places a reviewing agent consults to decide
whether unenforced trigger code is a finding. It would have suppressed correct
findings.

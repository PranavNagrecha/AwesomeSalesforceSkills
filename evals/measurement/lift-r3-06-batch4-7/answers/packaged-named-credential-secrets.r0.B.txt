**No. Tokens and secrets are not packaged.** The package carries the structure of the credential, not the values that authenticate it.

Per the packaging guide (pkg2 264 L9543-9567), packaged named credentials "don't include the access tokens or certificates that are needed to perform authenticated callouts."

**What travels with the package**
- The Named Credential definition: the `Url` parameter, its `Authentication` reference to an External Credential, and the type (`SecuredEndpoint` or `PrivateEndpoint`).
- The External Credential definition: the protocol and the principal parameters.
- Each named credential must be mapped to at least one external credential (pkg2 264 L9573-9574).

**What does not travel**
- OAuth access and refresh tokens
- Client secrets and passwords
- Signing certificates for JWT
- Per-user authentication state

**Why:** the same guide says the standard Metadata API "can't fully expose the definition of a credential and render sensitive information like tokens in plain text." Credentials are stored encrypted (meta 264 L92625-92627, L66152-66154). A plain Metadata API deploy behaves the same way, so the rule applies to change sets and SFDX deploys as well as packages.

**Post-install steps for the subscriber org** (pkg2 264 L9543-9567)
1. Create the principal, or populate the tokens and certificates, in the UI or through the Connect API.
   - For a Named Principal: Setup > Named Credential > External Credential (L9566).
   - For a Per User principal: each user authenticates at My Personal Information > External Credential (L9567).
2. Grant the permission sets access to the principal. This is `PermissionSet.externalCredentialPrincipalAccesses` (API 59.0+, value `ExternalCredential-Principal`), shown in the UI as "Enable External Credential Principals" (L9564).
3. Reauthenticate.
4. Run a test callout.

**For the package author**
- Document these steps in the install guide or a post-install runbook, because a subscriber's callouts won't work until they're done.
- Don't expect to ship a working, pre-authenticated integration.
- A permission set in the package can reference the principal, but the subscriber still has to supply the secrets.

**Unverified:** The corpus doesn't say how the failure shows up if steps are skipped (error text, or whether it fails silently). Check that in a test install before writing it into customer docs.

**No. Secrets and tokens are never packaged.** Only the metadata definition travels with the package. Credential values are always supplied in the subscriber org.

**What is packaged**
- **Named Credential:** the definition, such as the endpoint URL, the link to its External Credential, and the callout options.
- **External Credential:** the authentication protocol, the principal definitions, and the authentication parameter names.
- **Permission sets:** these can carry External Credential Principal Access, so users can be granted access to the principals.

**What is not packaged**
- Passwords, API keys, and client secrets entered on a principal.
- OAuth access and refresh tokens, whether from a named principal or from per-user authentication.
- Any per-user credentials, which exist only after each user authenticates in the subscriber org.

With the legacy Named Credential model, the endpoint and auth settings are packaged, but the password or secret is not. The same holds for the Auth Provider's consumer secret, which I'd expect the subscriber to re-enter. Verify that against the current docs for your package type.

**What this means for your package**
1. After install, the subscriber admin must configure each principal in Setup under External Credentials and enter the secret or run the OAuth flow. Document this as a required post-install step.
2. Assign the permission set that includes the principal access. Without it, callouts fail even when the credentials are populated.
3. For automated setup, a post-install script can call the `ConnectApi.NamedCredentials` credential methods, such as `createCredential`. The secret must still come from the subscriber, never from your package. Don't hardcode it.
4. Treat the packaged definition as a template. The same package installs into orgs with different credentials, which is the intended design.
5. If a callout fails right after install with an authentication error, check these first: principal not configured, permission set not assigned, or the OAuth flow not completed.

Also check which parts of the Named Credential and External Credential subscribers can edit after install. This differs between managed and unmanaged components and can change across API versions, so confirm it for your target version.
